## THE DATA MODEL / 03

Target + namespaced key + value.

- Targets: commit, change ID, path, branch, project.
- Strings for individual values.
- Lists for appended entries; sets for unique members.

## THE CLI / 04

```sh
git meta set commit:314e7f0fa7 agent:model "claude-opus-4-6[1m]"
git meta list:push branch:sc-feature-1 review:comments "love it"
git meta set:add path:src/metrics owners schacon
```

Keys can be deeply namespaced. Read a namespace to retrieve its subkeys.

<Notes>These commands come from the README examples. Refer to git-meta/spec for current CLI semantics.</Notes>

## COLLABORATION / 06

Separate keys become separate tree entries.

- Independent edits merge naturally.
- The README proposes local preference for conflicting values.
- Append-only list entries can combine across collaborators.
- Explicit tombstones express deletion; absence does not.

## SCALE / 07

Large transcripts should not make every clone enormous.

Blobless fetches bring down trees and commits. Pruned checkpoints keep a useful working set; older values can be fetched on demand.

Public, corporate and personal metadata can use separate destinations. Higher-level tools handle capture, display and synchronization.

The README reports about 500 MB of compressed transcript data versus less than 2 MB for its blobless example.
